# Context Passport

**A free Claude Code skill that generates one portable `CONTEXT.md` — a project-context file built to cold-start any AI tool.**

You switch from Claude to ChatGPT, or open Cursor, or spin up a fresh session — and the AI knows nothing about your project. So you paste the same three-paragraph explanation again. And again. And you can't remember what you told which tool.

Context Passport writes that explanation once, as a real file in your repo. Commit it, paste it into whatever tool you switch to, regenerate it when it drifts. It runs entirely locally in Claude Code — **no account, no signup, no API key, and your code never leaves your machine.**

---

## What it produces

A single `CONTEXT.md` at your repo root. It's not a repo dump — it carries only what a capable AI **can't** figure out by reading your code: the *why* behind decisions, the constraints that are invisible in the source, deliberate omissions, current work-in-progress, and your project's vocabulary. Everything derivable from the code is left out, because the receiving AI can just be told to read the files.

Here's a full example for a fictional project, "Tideline":

```markdown
# Context Passport — Tideline

> HOW TO USE THIS FILE: You are an AI assistant being cold-started on this project.
> Read this top to bottom before answering. It carries the decisions and constraints
> you can't infer from the code — it does NOT replace the code. When you need
> implementation detail, read the actual files. Treat everything below as current
> as of the generated-on date in the footer; if that's stale, ask me to regenerate it.

## One-liner
Tideline is a REST API that serves 7-day tide and current forecasts for 4,000 coastal
stations, sold to marine-navigation and fishing apps.

## Stack
Go 1.22 · Postgres 15 (TimescaleDB) · Redis (forecast cache) · deployed on Fly.io ·
NOAA CO-OPS as the upstream data source.

## Architecture (mental model)
- Ingestion worker pulls raw NOAA harmonic constituents nightly, not live readings.
- Forecasts are COMPUTED on demand from constituents, then cached in Redis for 6h.
- The API layer never touches NOAA directly — only the worker does.
- Stations are the top-level entity; everything hangs off station_id.
- TimescaleDB hypertables hold historical observations for the accuracy backtests only,
  not for serving forecasts.
- There is no user auth in the service — API keys are validated at the gateway (Kong).

## Conventions
- All timestamps are UTC in storage, converted at the serialization boundary only.
- Errors return RFC 7807 problem+json — do not invent ad-hoc error shapes.
- Tide heights are always meters in the DB; feet is a presentation concern.
- New endpoints require a backtest fixture before merge (see /backtests).

## Active decisions & constraints
- We compute forecasts instead of caching NOAA's because NOAA only publishes 48h;
  we need 7d. This is the core reason the worker exists — don't "simplify" it away.
- Redis is a cache, never a source of truth. Cold cache must always recompute.
- We deliberately do NOT store per-user data — keeps us out of GDPR scope. Keep it that way.
- Postgres connection pool is capped at 20; Fly instances are small. Don't add
  long-held transactions.

## Current focus
Adding current (water-flow) forecasts alongside tide-height forecasts. The constituent
math differs; work is on the `currents` branch. Accuracy backtest threshold is the blocker.

## Glossary
- Constituent: a harmonic component (e.g. M2, S2) used to compute tides. Our real input.
- Station: a NOAA measurement location; our top-level entity.
- Backtest: replaying a past window to score forecast accuracy vs recorded observations.
- Slack water: the moment current direction reverses — a product term, comes up in specs.

---
_Generated by Scribld Context Passport on 2026-07-06. This is a snapshot — regenerate
after major changes (`/context-passport`). Want it always current, and shared across every AI
tool automatically? → scribld.io_
```

Notice what's *not* there: no file listing, no function summaries, no "it uses Go because there's a go.mod." A cold ChatGPT reading this knows why the worker exists, why there's no user auth, and what "slack water" means — things it could never learn from a `grep`.

## CONTEXT.md vs CLAUDE.md

They look similar and do opposite jobs. Keep both.

| | **CLAUDE.md** | **CONTEXT.md** (passport) |
|---|---|---|
| **Answers** | "How should you *behave* in this repo?" | "What is this project and what do I need to know?" |
| **Audience** | Claude, specifically | Any AI assistant — ChatGPT, Gemini, Cursor, a fresh Claude |
| **Nature** | Standing instructions, behavioral | Project knowledge, informational |
| **Lifespan** | Permanent, tool-coupled | A snapshot in time, portable |

Short version: `CLAUDE.md` is how you want Claude to *act*. `CONTEXT.md` is what any tool needs to *understand* before it acts. One is behavioral and Claude-specific; the other is informational and tool-agnostic.

## Install

```bash
mkdir -p ~/.claude/skills/context-passport && \
  curl -fsSL https://raw.githubusercontent.com/getscribld/scribld-context-passport/main/SKILL.md \
  -o ~/.claude/skills/context-passport/SKILL.md
```

Manual alternative: create `~/.claude/skills/context-passport/`, download [`SKILL.md`](https://raw.githubusercontent.com/getscribld/scribld-context-passport/main/SKILL.md) from this repo, and drop it in that folder.

Then, in any project, run `/context-passport` or say "generate a context passport."

## FAQ

**Does this send my code anywhere?**
No. It runs entirely inside Claude Code on your machine. It reads your repo locally and writes one file. There's no account, no API call, no telemetry — nothing leaves your machine.

**How often should I regenerate?**
After anything that changes the *why*, not just the *what*: a new architectural decision, a shift in current focus, a constraint added or lifted. Day-to-day code changes don't need a regenerate — the passport carries the non-derivable core, and most commits don't move it. When you regenerate over an existing `CONTEXT.md`, the skill shows you what changed before writing.

**I have a monorepo.**
The skill detects multiple packages and asks whether you want a passport for a specific package or a top-level "boundary" passport that names the sub-packages and how they relate. It won't silently pick one for you.

**What if my project is brand new, or has no README?**
It generates from whatever exists and marks thin sections `[TODO — not enough signal yet]` rather than inventing architecture. If there's no README, it flags that in the output so the gaps are known, not silent.

## The honest pitch

A passport is a snapshot, and snapshots go stale. That's the format's real limitation — a cold AI will confidently act on an out-of-date constraint. The header and footer tell the receiving tool to distrust an old passport, but the deeper fix is to not have a snapshot at all.

That's what [Scribld](https://scribld.io) is: the live version of this file. Its MCP server means your tools already share one memory — you don't paste anything, and it's never stale. Context Passport is the manual version of what Scribld does automatically. If pasting-and-drifting is a tax you pay every day, that's the tax Scribld removes.
